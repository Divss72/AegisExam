1. Executive Summary & Core Security Reality

AegisExam Sentinel is an in-browser online examination platform providing a LeetCode-style coding workspace, question authoring studio, best-effort screenshot deterrence, and a forensic watermark extraction laboratory.

The Fundamental Browser Limitation: A standard web application operates inside a sandboxed browser process. JavaScript has no driver-level API or operating system permission to command the OS GPU compositor to discard framebuffer pixels. Streaming platforms (like Netflix) produce black screenshots solely because they rely on Hardware DRM (Widevine/HDCP) which encrypts the hardware video path directly to the monitor. Widevine only supports audio/video codecs and cannot be applied to general HTML DOM nodes, text, or questions.

Important Engineering Rule: Do not claim that CSS overlays, transparent divs, or canvas tags can guarantee that OS-level screenshots turn black. AegisExam implements the strongest feasible browser-based protections using a Defense-in-Depth pipeline, clearly separates active controls from simulated testing tools, and irrevocably ties any leaked material to the candidate's identity.

2. The 6-Layer Screenshot Detection & Deterrence Pipeline

Scenario: Candidate takes a photograph of the monitor using an external smartphone camera. Watermark: Candidate Name, Student ID, IP Address, Session Token, and Timestamp embedded into pixels. Forensic Engine: Extracts metadata and matches backend examination database with 99.8%+ certainty.

3. Step-by-Step Mechanism Implementation

Layer 1: Pre-Emptive Key Interception (Capturing Phase)

Standard DOM listeners bubble from the target element upwards. By registering listeners on window with useCapture: true, keystrokes are intercepted before standard browser handlers execute: 

window.addEventListener('keydown', (e) => {
  const isWindowsKey = e.key === 'Meta' || e.code === 'MetaLeft' || e.code === 'MetaRight';
  const isPrintScreen = e.key === 'PrintScreen' || e.keyCode === 44;
  const isAltKey = e.key === 'Alt';
  const isDevTools = (e.ctrlKey && e.shiftKey) || e.key === 'F12';

  if (isWindowsKey || isPrintScreen || isAltKey || isDevTools) {
    wipeAllCanvasesBlack(); // 0ms buffer wipe
    if (isPrintScreen) handlePrintScreenAttempt();
    else triggerTargetedBlackout('Shortcut intercepted.');
  }
}, true); // Capturing phase execution

Layer 2: 0ms Synchronous Canvas Buffer Memory Wiping

Modifying CSS properties requires layout recalculation (16–33ms), giving OS utilities time to capture the screen. AegisExam rasterizes content to HTML5 Canvas and calls ctx.fillRect synchronously: 

function wipeCanvasBlack(canvas) {
  const ctx = canvas.getContext('2d');
  ctx.save();
  ctx.setTransform(1, 0, 0, 1, 0, 0);
  ctx.fillStyle = '#000000';
  ctx.fillRect(0, 0, canvas.width, canvas.height); // 0ms memory wipe
  ctx.fillStyle = '#f43f5e';
  ctx.fillText('CONTENT BLACKED OUT • ANTI-CAPTURE SHIELD ENGAGED', canvas.width / 2, canvas.height / 2);
  ctx.restore();
}

Layer 3: Focus-Loss Blackout (Snipping Tool Defeat)

When Windows Snipping Tool (Win+Shift+S) or third-party capture software runs, the browser window temporarily loses focus. The blur and visibilitychange listeners fire instantly: 

window.addEventListener('blur', () => {
  wipeAllCanvasesBlack();
  triggerTargetedBlackout('Focus lost: Snipping Tool or external tool detected.');
  recordViolation('Focus Loss / Potential Screen Capture');
});

Layer 4: Targeted Question Obscurity (OPSWAT ASC Model)

Rather than locking the candidate out with a disruptive full-page modal, only the question container (#student-targeted-shield) wipes black. The candidate can continue coding, see their timer, and click [ Click to Unlock Question ] to acknowledge the incident.
